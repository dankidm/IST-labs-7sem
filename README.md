# ИИ-платформа базы знаний и маркетинга

Лабораторные работы 1–5 по дисциплине «Информационные системы и технологии».
Команда №11, МГТУ «СТАНКИН», 2026 год.

Репозиторий содержит архитектуру проектируемой платформы в PlantUML
и учебные прототипы отдельных компонентов. Платформа объединяет
корпоративную базу знаний, рыночную аналитику, RAG и подготовку материалов.

## Структура

- `src` — исходники диаграмм по типам представлений.
- `docs/images` — сохранённые изображения прежней сборки; актуальные PNG публикуются
  в артефакте `diagrams` каждого успешного запуска GitHub Actions.
- `.github/workflows/render-docs.yml` — проверка и генерация документации.
- `code/analyst_code` — прототип модуля экспорта со стратегиями CSV/XLSX/PDF.
- `code/code_backend` — прототип гибридного поиска.

`code/code_vibecoder` сейчас записан в Git как ссылка на вложенный репозиторий

корректный URL подмодуля. Заменять ссылку пустой папкой нельзя считать

репозитория; сам дефект импорта кода остаётся открытым.

## Локальный просмотр через Docker

После запуска Docker Desktop создать контейнер один раз:

```bash
docker run -d \
  --name ist-lab5-plantuml \
  -p 127.0.0.1:8080:8080 \
  plantuml/plantuml-server:jetty
```

Для существующего остановленного контейнера: `docker start ist-lab5-plantuml`.
Проверить статус командой `docker ps --filter name=ist-lab5-plantuml`.
Веб-интерфейс сервера: http://localhost:8080.

В настройках рабочей области VS Code:

```json
{
  "plantuml.render": "PlantUMLServer",
  "plantuml.server": "http://localhost:8080"
}
```

Открыть `.puml` и нажать Alt+D / Option+D. Используемые подключения C4 через
`!include https://raw.githubusercontent.com/...` требуют доступа к сети.
PlantUML Server является инструментом отрисовки архитектуры.

## Проверка и генерация в GitHub Actions

Workflow запускается на каждый PR в `main`, на push в `main` и вручную
через `workflow_dispatch`. Фильтр по путям отсутствует: обязательная проверка
доступна также для PR с изменениями документации или настроек сборки.

1. Получает исходники; настраивает Java 21, Graphviz и PlantUML.
2. Проверяет наличие и синтаксис `.puml` в `src`; при ошибке шаг завершается с ошибкой.
3. Генерирует PNG в отдельный временный каталог runner, без старых изображений.
4. Выводит список и количество новых PNG в лог и публикует артефакт `diagrams`.

У workflow права `contents: read`. Публикация выполняется через артефакты,
поэтому защита `main` обязательными PR не препятствует сборке.

Актуальные изображения находятся на странице нужного запуска
[Render PlantUML docs](https://github.com/dankidm/IST-labs-7sem/actions/workflows/render-docs.yml)
в разделе Artifacts → diagrams. Архив сохраняется в GitHub Actions на 90 дней;
логи и итоговый архив следует скачать для отчёта и индивидуальной защиты.
Имена файлов в таблице выше соответствуют содержимому артефакта.

## Порядок интеграции

1. Создать отдельную ветку от актуального `origin/main`.
2. Изменить исходники и проверить их локально.
3. Открыть PR в `main`, указать смысл изменений и результаты проверки.
4. Дождаться успешной проверки `render` и содержательного ревью.
5. Исправить замечания, затем выполнить слияние через принятый командой процесс.
6. Сохранить ссылку на запуск, его логи и артефакт для отчёта ЛР5.

Синтаксические проверки и успешный рендеринг не заменяют ревью границ,
общих ID и согласованности протоколов между уровнями C4.
