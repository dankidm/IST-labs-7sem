# ИИ-платформа базы знаний и маркетинга

## О проекте

**ИИ-платформа базы знаний и маркетинга** — учебный проект по проектированию архитектуры информационных систем.

В рамках лабораторных работ разрабатывается архитектура **ИИ-платформы корпоративной базы знаний и маркетинга**. Платформа предназначена для централизованного хранения информации о продуктах, проектах и кейсах компании, интеллектуального поиска по документам, анализа рыночных данных и автоматизированного создания маркетинговых материалов.

Архитектура описывается с использованием модели **C4**, языка **PlantUML** и подхода **Diagrams-as-Code**.

## Основные возможности системы

- Хранение и поиск корпоративных документов, продуктов и кейсов.
- Семантический поиск с использованием RAG.
- Взаимодействие с ИИ-агентом через веб- и мобильное приложения.
- Генерация презентаций, коммерческих предложений и других маркетинговых материалов.
- Сбор и анализ рыночных данных.
- Формирование аналитических отчётов и дайджестов.
- Интеграция с CRM, корпоративными системами авторизации и сервисами уведомлений.
- Использование локальных и облачных языковых моделей.

## Архитектура системы

Для документирования используется модель **C4**, позволяющая рассматривать систему на нескольких уровнях детализации.

| Диаграмма | Назначение |
|---|---|
| L0 — System Landscape | Место платформы среди других информационных систем |
| L1 — System Context | Пользователи, внешние системы и взаимодействия |
| L2 — Containers | Основные приложения, сервисы и хранилища |
| L3 — Components | Внутреннее устройство отдельных сервисов |
| L4 — Code / Classes | Структура классов и реализация паттернов проектирования |
| Dynamic | Последовательность взаимодействий в бизнес-сценариях |
| Deployment | Размещение сервисов на инфраструктуре |

### Основные подсистемы

**Клиентские приложения и ИИ-контур (Vibecoder)**

Включают веб-приложение на React, мобильное приложение на React Native, ИИ-агента на FastAPI и LangGraph, а также сервис генерации материалов.

ИИ-агент выполняет поиск корпоративных знаний, формирует контекст запроса и обращается к языковым моделям. Для переключения между локальными и облачными моделями предусмотрен паттерн проектирования **Strategy**.

**Серверная часть (Backend)**

Обеспечивает управление корпоративными знаниями, обработку документов, поиск, разграничение доступа и интеграцию с другими сервисами.

**Аналитическая подсистема (Analyst)**

Отвечает за сбор рыночных данных, расчёт показателей, формирование аналитических витрин, отчётов и дайджестов.

**Общая инфраструктура**

Включает API-шлюз, реляционную и векторную базы данных, объектное хранилище, брокер сообщений, кэш, LLM-сервер и средства мониторинга.

## Просмотр и генерация диаграмм

Диаграммы хранятся в текстовом формате `.puml`, что позволяет отслеживать изменения архитектуры через Git.

Для локальной генерации изображений можно установить PlantUML и Java либо воспользоваться расширением PlantUML для Visual Studio Code.

Пример генерации PNG:

```bash
java -jar plantuml.jar -tpng src/context/vibecoder_context.puml
```

Пример генерации SVG:

```bash
java -jar plantuml.jar -tsvg src/components/vibecoder_components.puml
```

Для диаграмм C4 используется библиотека C4-PlantUML. При генерации требуется доступ к её исходникам либо локально настроенные зависимости.

## CI/CD — автоматизация документации

В рамках лабораторной работы №5 предусматривается настройка GitHub Actions для автоматической проверки и генерации архитектурных диаграмм.

Целевой процесс:

1. Разработчик создаёт отдельную Git-ветку.
2. Вносит изменения в файлы `.puml`.
3. Создаёт Pull Request в основную ветку `main`.
4. GitHub Actions проверяет синтаксис PlantUML.
5. При успешной проверке формируются изображения диаграмм.
6. Тимлид проводит Code Review.
7. После одобрения изменения объединяются с `main`.

Планируемая конфигурация автоматизации: `.github/workflows/render-docs.yml`.

**Статус:** настройка CI/CD выполняется в рамках ЛР №5.

## Результат проекта

Результатом является единый репозиторий архитектурной документации, в котором:

- диаграммы представлены в виде исходного кода PlantUML;
- архитектурные решения согласованы между подсистемами;
- история изменений хранится в Git;
- вклад участников фиксируется через коммиты и Pull Requests;
- предусматривается автоматическая проверка и генерация диаграмм.

Такой подход позволяет поддерживать архитектурную документацию вместе с развитием программной системы.
